# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An MCP server exposing a story-world knowledge graph backed by [Anytype](https://developers.anytype.io/). The graph (characters, locations, events, prose) is the source of truth; an LLM builds the world and renders scenes from it via thirteen stdio MCP tools. Design docs: `docs/adr/` (decisions), `docs/WORK_PACKAGES.md` (roadmap/status), `docs/TESTING.md` (suites, live E2E, goldens, behavioral evals, demo scripts), README (setup + layout table).

## Environment constraints

The devcontainer applies an egress firewall (`.devcontainer/init-firewall.sh`): **most web connections are blocked**. Don't assume `curl`/`pip install <new-package>` will reach the internet. If a new package or dependency is needed, **ask the user first** — they will add it to the Docker container setup.

### Live E2E (real Anytype server)

```bash
ANYTYPE_E2E=1 python -m pytest tests/e2e -q
```

Runs against the **headless sidecar** (`anytype` compose service, part of the default stack since the WP14 cutover, ADR 019): compose sets `ANYTYPE_API_BASE_URL=http://anytype:31012` and `ANYTYPE_API_KEY_FILE=.devcontainer/secrets/anytype_api_key` (the BOT account's key). The desktop app is not needed — the suite find-or-creates a space named exactly `GC-E2E` on the bot account and **resets it before and after each run** (the local API cannot delete spaces); spike artifacts do not survive a run, the spike scripts reseed themselves. With the sidecar's rate limit disabled the whole suite runs in ~10s (the old desktop endpoint throttled writes to ~1 req/s). The desktop app on the host remains the human surface; to point tooling at it temporarily, override `ANYTYPE_BASE_URL=http://host.docker.internal:31009` with a desktop-issued key.

## Architecture

Ports-and-adapters with a strict, **machine-enforced** dependency rule (import-linter contracts in `pyproject.toml` — violations fail CI):

```
interface ──▶ application ──▶ domain
(MCP tools,    (use-cases,     (pure logic: graph, traversal,
 presenters)    one per tool)    schema, session — no I/O, no clocks)
                    │
                    ▼
                  ports ◀── implemented by ── infrastructure
             (GraphRepository,               (in-memory fake +
              SessionStore)                   Anytype adapter)
```

Only the composition root (`interface/server.py`) and tests may import `infrastructure`; it is also the only module importing the MCP SDK.

Key ideas that span multiple files:

- **Anytype is storage + the human editing surface, never the traversal engine.** Its API only text-searches names/snippets, so all traversal runs on `domain/graph.py`'s `GraphIndex` — a derived, rebuildable projection. Repository adapters keep it coherent: write-through on our writes, hydrate/resync for edits humans make in the Anytype UI (with self-write suppression in `infrastructure/anytype/repository.py`).
- **Space-reflecting open schema (ADR 006).** The server reflects the user's *existing* space: native types are node types, every `objects`-format relation is a labelled edge. There is no closed `gc_` vocabulary; `gc_` keys survive only for infrastructure (Prose, SessionContext, and the stale-flag/story-time scalars — summaries live in the built-in `description` property per ADR 011, long-form descriptions in the body per ADR 010). Everything the server writes is a REAL Anytype property or the object body (ADR 028) — the old `gc_fields` JSON blob is retired: session snapshots live in `gc_chat_session`, recorder attribution in the minted `gc_generated_at`/`gc_user_id`/`gc_model`/`gc_mode`/`gc_origin` properties (`domain/attribution.py`). `infrastructure/anytype/registry.py` resolves requested types/relation labels against what the space actually has.
- **Fakes are contracts.** `tests/contract/` runs the same suite against `InMemoryGraphRepository` and the (mock-backed) `AnytypeGraphRepository`. Any behavior added to the Anytype adapter must land in the fake too, with a test; if the fake can't express it, fix the port. The live-gated `tests/e2e/` suite runs the same contracts against a real server.
- **Quirk quarantine.** All Anytype representation assumptions (A1–A14) live in `infrastructure/anytype/mapping.py`, mirrored by `mock_server.py` (`MockAnytype`), which pins live-server behavior confirmed by spikes (search caps, the body-editing field-name mismatch — create `body`, update `markdown`, never in list/search (ADR 010) — timestamps-from-properties, fresh-relation settle window).
- **The consumer of every tool response and error string is an LLM.** Tool docstrings are prompts (`interface/server.py`); errors derive from `GraphContextError` and echo allowed values so the model can self-correct. Response-budget shaping lives in `interface/presenters.py`, not in tested logic.
- **Cross-turn context is curated, echoed once per turn (ADR 020, WP15).** The model keeps a scratchpad (`context action="note"`, replaced wholesale) and a `WorkingSet` of explicitly held nodes in granularity buckets (≤2 `full` with body + one-hop edges, ≤6 `summaries`); `interface/context_block.py` renders them plus the automatic recent trail as the first transcript event of every orchestrator turn — once per turn, budget-degraded, never per-response (the old per-response header was removed 2026-07-06 as token waste). The pipeline's `ConversationMemory` replays prior user/assistant messages ahead of the block; `/clear` empties it via a persisted order-id watermark, never by deleting chat messages.
- **Sessions are keyed per chat (ADR 021, WP8).** Every session — each chat thread, Discord channel, the CLI, the MCP client — is addressed by an explicit key (`anytype:<chat_id>`, `discord:<channel_id>`, `mcp`, `cli`) and owns its own `SessionState` + one `gc_session_context` node discriminated by `gc_session_key`. There is no unkeyed/default session (`SessionStore.load/save` require the key). `application/session_registry.py` is the sole source of live sessions; `composition` exposes `services_for(key)`, and the pipeline hands each session id a `Services` view over the shared repository. The Anytype bot serves every chat in a bound space (minus `exclude_chats`) as its own thread, with live discovery of new chats; all chats of one space share one runtime (turns serialize per space). Mode is persisted per chat.
- **Live chat streams are a capped, activity-ranked resource (ADR 043, WP35).** Each SSE stream pins a pooled connection for its lifetime, so only the `GC_CHAT_STREAM_CAP` (default 20) most recently active chats per space hold serve tasks; the rest hibernate — registered, sessioned, reachable by scheduled events and replies — and wake within one rescan tick: the `/chats` re-list `_watch_chats` already makes carries the server-maintained `last_message_date` (quirk C13, pinned in `chat.py`/`MockAnytype`; `list_chats` returns `ChatSummary` records), and the pure `plan_streams` (`anytype_chat_transport`) recomputes memoryless top-N each tick — a message makes its chat the newest, its stream starts, catch-up answers the message, and the least recently active idle stream stops (busy chats — mid-turn or holding a pending WP33 confirm — are never stopped; plan and cancel run with no await between). Chats hibernated at startup get one stream-less `_catch_up` from the watcher (ADR 019's offline-backlog promise survives the cap). Cap `0`/`off` streams everything; rescan off ignores the cap loudly (the poll is the only wake mechanism); pinned bindings are never capped.
- **Scheduled Events are timed prompts stored as nodes (ADR 027, WP18).** A `gc_scheduled_event` node (infra role `ScheduledEvent`) carries `gc_schedule` (one-shot ISO local datetime or five-field cron), `gc_schedule_prompt`, a `gc_schedule_status` select (Pending fires; Completed/Cancelled inert; empty = Pending; cancel preserves the schedule — re-enable by flipping to Pending), `gc_last_fired`, and the target chat's `gc_session_key`. These are REAL properties with human display names (`GC_REFLECTED_FIELD_KEYS` overrides the registry's `gc_` reflection exclusion for this surface — the attribution stamps share it since ADR 028); humans author events directly in Anytype (an explainer object is seeded with the type), the LLM via the `schedule` tool (bound in every mode, like `context`). Timing rules are pure (`domain/scheduling.py`, dependency-free cron): recurring events fire only once ARMED via a first `gc_last_fired` stamp, downtime collapses to one late fire. Only the Anytype bot fires them: `_watch_schedule` marks the node fired (at-most-once, one-shots → Completed) then injects a turn through `handle_message` under the route lock (`run_scheduled` in the transport; no "Processing…" placeholder — nothing posts until the reply is ready).
- **Automation Rules are reactive automations stored as nodes (ADR 039, WP31).** A `gc_rule` node (infra role `AutomationRule`, display "Automation Rule") watches ONE scalar property on ONE type and runs a built-in action on a value TRANSITION — conditions `changed to true|false|changed`, actions `set property to now | set property value | uncheck others of type | run script` (WP32, ADR 040). `set property to now` is format-aware (R2 live probe, amended 2026-07-19): date targets get local midnight WITH its explicit UTC offset (the live server rejects naive timestamps, and stores a bare date as midnight UTC — which displayed a day early in US zones; zone from `local_zone(GC_TIMEZONE)`, empty = system offset at write time), text targets the full local stamp. **`run script` (ADR 040)** executes the rule body's first fenced ```python block in a subprocess sandbox (`ports/script_runner.py` → `infrastructure/sandbox/`: `python -I -S` child, self-applied rlimits, scrubbed env, wall-clock kill via `GC_RULE_SCRIPT_TIMEOUT_SECONDS` default 5s; after SIGKILL the runner DRAINS pipes to EOF or `process.wait()` hangs — load-bearing). The child reads a full non-infra graph snapshot (cap 2000 nodes) with a tiny API (`objects/find/field/neighbors/set/log` + injected `now`) and queues ≤20 effects; the engine validates all-then-applies-all through its normal write path, so scripts inherit the no-cascade/at-most-once guarantees. Threat model: contains the owner's ACCIDENTS (loops, memory bombs, output floods), not a hostile author. The **`automation` tool** (bound in every mode like `schedule`, MCP-registered) is the LLM surface: create/update (tool-boundary validation), list, pause/resume (no hard delete — the port has no archive), and `test` = a dry run through the real sandbox + production validation that reports `would set …` lines and applies nothing (works on stored rules AND inline drafts). Nine `gc_rule_*` properties (all in `GC_REFLECTED_FIELD_KEYS`), authored entirely in the Anytype UI (explainer seeded with the type; no LLM tool). The engine (`domain/rules.py` pure matching; `application/rule_engine.py` `RuleEngine`, no new port — rules read off the graph by role like the scheduler) keeps an in-memory baseline of watched values per space, diffs it each tick, and REBUILDS it from the post-action index: nothing fires on restart/replay, transitions are consumed at-most-once (failures land in `gc_rule_last_error`, no retry), and the engine's own writes can never trigger a rule — rules do not cascade, by construction. Change detection is REST polling (the gRPC event backbone stays shelved, `docs/spikes/grpc-event-backbone.md`): the `rules` listener of the unified change tick (ADR 044, below) runs after its resync under the route lock. The status select is lenient (empty = Active; `Paused` is the human's word; `Error` is engine-owned and self-heals once the config parses — bookkeeping writes are change-only).
- **Change-driven reactions share one tick; mode config auto-refreshes (ADR 044, WP36).** The bot's `_watch_changes` (fourth watcher, replacing WP31's `_watch_rules`; `GC_CHANGE_TICK_SECONDS` default 5, `off` disables, `GC_RULE_TICK_SECONDS` honored as a compat alias) runs ONE modified-since resync per tick under the route lock, then an ordered list of named listeners (`_change_listeners`: `rules` first — ADR 039's 5s latency contract — then `modes`), each with its own crash guard; a future on-change feature is one listener, not a new watcher. The `modes` listener calls the public `Orchestrator.refresh_modes()`: `modes.mode_fingerprint` — `(id, modified_at)` over `Role.MODE`/`Role.SPACE_CONTEXT` index nodes — gates the reload (no-change ticks are free; `ModeConfigWatch` seeds its baseline on the first check, so nothing reloads on restart), and a detected change runs `/mode`'s `_refresh_registry` degrade path (last good registry kept, errors logged not posted). At-most-once per change: the baseline advances even on a failed reload — the human's next edit retries; `/mode` stays the unconditional reload. Net: editing an Activity Mode object or relinking `gc_default_mode` in the Anytype UI is live within ~one tick, no `/mode` or restart; ADR 034's semantics (default affects only new chats; per-turn spec lookup; vanished modes degrade) are unchanged.
- **Meta-inspection: the Space Setup mode authors modes; everyone else is locked out of infra writes (ADR 045, WP37).** `ModeSpec.meta_inspection` (the `gc_mode_meta_inspection` checkbox, threaded through every `mutating`-style seam; keys/formats domain-homed in `activity.MODE_CONFIG_FIELDS`) grants a mode the meta surface for `Role.MODE` ONLY: `modes.invoke` stamps `Services.visible_infra_roles` per call (empty for ordinary modes and the bare MCP server), the read surfaces honor it (`query`'s exclude-set and its infra hatch — which now REFUSES `type="Activity Mode"` unprivileged, closing a pre-045 leak; `find_by_name`/`resolve` and `get_node` neighbors via `include_roles`; the port catalogs `known_node_types`/`field_catalog` on both backends), and `gc_mode_*` reflects into `Node.fields`. Enforcement is new, in one place: `schema.validate_infra_write` (raising `InfraWriteDenied`, an errors-are-prompts message naming the escape hatches) runs in `NodeWriter` create/update with the caller's admitted roles — before this, hiding was discoverability-only and any mutating mode could write a guessed infra type; the dedicated infra writers (scheduler, rule engine, recorders) bypass NodeWriter and never meet it. The `space_setup` starter mode (all three seed corpora, marked default — FRESH spaces start in it; `mutating` + `meta_inspection`) interviews the user, creates a tailored Activity Mode object via `create_node` (its goal enumerates every mode option), proposes types via the ADR 041 flow, and suggests rules/schedules; setting `gc_default_mode` stays human-only (`SYSTEM_RELATION_DENYLIST` unpierced). Seed-once stands: already-seeded spaces get the mode from the one-time idempotent `scripts/seed_space_setup_mode.py`, which never touches the default link.
- **Schema changes are LLM-drafted, 👍-reaction-confirmed (ADR 041, WP33).** The `schema` tool (bound in every mode like `schedule`, MCP-registered) lets the model DRAFT a new type (`propose_type`) or new properties on an existing type (`propose_fields`) — `PropertyDraft` domain values (construction-validated; formats = the ADR 023 scalars + `objects` since ADR 042, whose no-scalar-shadow rule survives sharpened: a scalar draft naming an existing relation is an A12 format conflict, an `objects` draft naming one is a reuse-attach by id) in a session-scoped in-memory ledger (`application/schema_proposals.py`, cap 5, drafts not records). The tool has **NO apply action** — that absence is the guarantee: drafts drain after the reply as `confirm` reply events (WP23-outbox discipline; text rendered from the STORED proposal, never the model's paraphrase), the Anytype transport posts each as its OWN message + "React 👍 to APPLY / 👎 to dismiss" and arms `pending_confirms`; `handle_reaction` (fed by C12 `reactions_updated` SSE frames + a tracked-message re-list sweep on reconnect, since reaction frames don't replay) applies on any non-bot identity's 👍 under the route lock with no model turn, dismisses on 👎, ignores the bot's own identity, and posts ✅/🗑/⚠ outcomes. Restart clears drafts and watches together (stale 👍 = inert); Discord/CLI render a where-to-confirm note; the bare MCP server drafts but can never apply. Quirk C12 (spike S15): `POST …/messages/:id/reactions {"emoji"}` toggles; `reactions` = emoji → ACCOUNT identities. Apply lands via two contract-tested port methods — `GraphRepository.create_type` / `add_type_properties` — with shared semantics: same-name/same-format space properties are reused (attached), format mismatch (A12) / relation shadowing (ADR 006) / existing type name raise `SchemaChangeConflict`, already-on-type drafts are retry-safe no-ops. The Anytype adapter is A11-safe (re-fetch inside the single-writer section, resend full property list + additions — bootstrap's retrofit discipline), registers the result in the live `SpaceRegistry` (`register_type`) so `create_node` targets it with no resync, and seeds select options find-or-create as tags.
- **One `properties` surface on the write tools (ADR 042, WP34; resolution type-scoped by ADR 047, WP39).** `create_node`/`update_node` take a single `properties` dict — scalars and relations together, discriminated by what the target TYPE (plus, on update, the object itself) says the key IS: a key naming an `objects` relation the type carries takes a node id/name (or a list) and becomes link(s), everything else is a scalar; JSON-native values coerce at the tool boundary (bool, numbers, string lists), rejected loudly by property name — never a crash. Bare keys resolve ONLY against the type's attached properties (update adds the object's own instance vocabulary; infra-role writers, the seeded `gc_edge_*` starter relations, and the ADR 028 attribution stamps — which recorders write onto NATIVE artifact types per ADR 015 — stay space-wide) — an unattached space property needs one explicit `create_missing_properties` declaration, which REUSES the existing property (attach, never a twin; the live-caught alternative was an unattached near-duplicate relation spreading silently). The port seam is `relation_label_for(key, on_type=|on_node=)` (exactly one, mandatory); the sectioned unmatched-key error teaches the type's own vocabulary first, then the attach gesture, naming the exact unattached match when there is one. On update, relation entries APPEND (`remove_links` for removals; reassignment = add + remove); incoming links are retired (`LinkSpec.outgoing` is gone — the reverse edge is the other node's own write, deleting the composite-create's patch-other-objects choreography; the outgoing-failure rollback survives). New keys stay explicitly declared: `create_missing_properties={key: {"format": F, "scope": "instance"|"type", "name"?}}` (string shorthand = instance; formats = ADR 023 scalars + `objects`, folding relation minting into the same declaration). `instance` = space-level mint, value on the one object; `type` = the SAME immediate mint + value AND an auto-drafted EXTEND_TYPE proposal into ADR 041's ledger (`NodeWriter` → `SchemaProposals`, riding the 👍 flow unchanged — the human gate on all type changes stays; type-attach is what makes a property rule-watchable; a drafting failure degrades to a warning, a landed write is never unwound). The retired params — `fields`, `links`/`add_links`, `create_missing_relations`, `create_missing_fields` — survive as dead parameters raising a self-correcting redirect. Built-in rule watchable: `modified_at` (aliases like "last modified date"; vocabulary in `domain/rules.py`) resolves as a `changed`-only watch on ANY type unless the space's own catalog claims the name — both backends keep `Node.modified_at` truthful on every write (the fake's deterministic monotonic clock; the adapter folds link-write PATCH responses back into the index). `NodeWriter` returns `WriteOutcome` (node + drafted proposals + warnings); quirk A14 (duplicate property key 400s) maps to a typed conflict, a declared key matching a same-format property is a silent reuse.
- **Document modes: the manuscript lives in a node, not the chat (ADR 048, WP40).** A mode with `gc_mode_document_type` (text, e.g. `Chapter`; requires `mutating`, mutually exclusive with `gc_capture_type` — capture survives only for modes whose replies ARE the artifact) has the MODEL maintain the document node through the normal write tools: create once, revise the same node's `description`, curate its `references` itself. `modes.goal_for(spec)` appends the standing `DOCUMENT_GUIDANCE` block in one place (the pipeline's prompt fingerprint, diary, and `decide` all route through it); the pipeline stamps the turn's touched document-typed nodes onto `ReplyEvent.attach` beside the intent card (never filtered by `hide_node_cards` — the reply only summarizes, the card is the link), and `_finish_turn` drains the journal unconditionally. Reply discipline is prompt-only by decision — no harness reply rewriting.
- **Node revision history is space-level data config (ADR 049, WP41).** The Space Context's `gc_tracked_types` text list ("Tracked types") names the node types whose BODIES get revision history — writes from any mode and human Anytype-UI edits both record; infra types never track. Identity is normalized paragraph hashes (`domain/revisions.py`, the ONLY place bodies are compared — absorbs A9/A13/whitespace drift per ADR 010's no-byte-exact rule; moves keep identity, so blame needs no anchoring); history is a keyframe+delta JSONL log inside one fence in a hidden `gc_node_history` sidecar per tracked node (`gc_history_of` discriminator, `gc_session_key` pattern; lenient parse; ~400K soft cap, compaction drops oldest layers but re-carries live block texts). `application/node_historian.py` records compare-to-baseline — baselines ALWAYS from `fetch_body` output, so store normalization never mints phantom revisions — at two points: the turn boundary (one `model · mode · user` revision per touched tracked node; failures never fail the turn) and the `history` listener (third on the ADR 044 change tick; author `human` — the API exposes no last-modified-by, open spike). `rebuild()` restores baselines at startup and catches up offline edits; blame derives at read time (introduced-by + difflib lineage), never stored. Fenced-JSONL body round-trip is contract-tested on both backends and live-confirmed (`docs/spikes/node-history-body.md`). WP42/43 (ADR 050) built the review layer on top — next bullet.
- **Section review state, locked sections, and the prose page (ADR 050, WP42/43).** Per-block `status` (`raw_ai|approved|human`) and `intent` (`locked|flexible|needs_change`) marks are extra line kinds in the SAME sidecar log (no seq — file order is fold order; old readers skip them leniently); `revisions.section_states` folds the interleaved log into current state keyed to the final sequence, with lineage through the one shared similarity rule (`closest`): a HUMAN edit's successor inherits status AND intent (a no-ancestor human block starts `human`; editing ≠ approving), a MODEL edit drops the successor to `raw_ai` (any AI edit voids `approved`) while intent follows; compaction hoists live dropped-era marks. Locked enforcement is ONE rule at the write chokepoint: `NodeWriter` consults an injected `SectionGuard` (the historian's sync `check_body_update` — order-insensitive `missing_locked` presence check, no diffing) and raises `LockedSectionsChanged` errors-are-prompts; bootstrap LATE-BINDS the historian onto the donor `Services` (`services.historian`) so every derived session writer is guarded — the bare MCP server has no historian and no guard (ADR 049 v1 scope), and infra writers bypass NodeWriter entirely (locked binds the model, never the human in Anytype). The `edit_document` mutation tool (read-only modes never bind it) splices ONE section by hash anchor (`sections|replace|insert_after|delete`; unique prefixes; `top` prepends) through `application/document_editor.py` → the session writer, so guard/journal/staleness apply for free and untouched blocks keep their hashes verbatim; tracked FULL working-set entries render per block as `[§hash · intent]` in the context block. The editor UI is `prose.html` on the inspection server (mobile-first; since WP48 a CodeMirror 6 page — next bullet): `orchestrator/prose_bridge.py` is the only thread/loop door (an empty registry handed to `create_server` pre-bootstrap; spaces register historian+repository+route-lock handles; every page read/write hops via `run_coroutine_threadsafe` onto the owning loop, writes under the route lock, 15s → 504), and the write POSTs are doubly gated — same-origin check plus `GC_PROSE_TOKEN` bearer (unset = read-only page 403; bad token 401 → the page prompts once; stale base/hash 409 → reconcile). Accepted failure modes (guard-freshness window between change ticks; revision-derived state not surviving compaction; normalized text in historical diffs) are in the ADR. **WP44/45 (ADR 051):** consecutive HUMAN revisions coalesce into one pending revision (`revisions.rollup_base` + historian re-record against the trimmed base — same seq, cadence survives; a model revision or ANY mark solidifies by displacing the tail; full undo REMOVES the pending revision; refuses over a marker-then-keyframe log), and `revisions.word_authorship` derives per-word author spans (ancestor inheritance via `closest` WITHOUT match consumption — split paragraphs inherit in both halves; restored hashes keep authorship) which the doc wire serves and the page renders as highlighted human-typed words — display derivation only, nothing stored. **WP46 (ADR 052):** review state itself went token-grained — `SectionMark` carries an optional token range (`s`/`e`; absent = whole block), `revisions.token_states` folds per-token status/intent with the same positional inheritance (an AI edit voids `approved` only on the words it changed; `section_states` is now the derived badge view: all-agree → approved/human, mixed → raw_ai, intent = strictest token), and locked enforcement is verbatim-RUN presence (`locked_runs` substring check — the model may edit around or move locked text, never alter it; the context block lists `locked verbatim: "…"` under partially locked blocks). Selecting text opens the action bar with one ranged target per touched paragraph; state indicators render as one background highlight per word (locked > needs_change > approved > human-typed lavender, ADR 053 amendment).
- **The prose editor: CodeMirror, raw indexing, a document wire (ADR 054, WP48 — supersedes ADR 053's no-library/block-editing and ADR 052's normalized indexing).** The page is ONE CodeMirror 6 editor over the whole raw body — direct inline typing, styled-raw markdown (never WYSIWYG: a markdown serializer rewrites source text, reintroducing drift). The bundle is vendored PREBUILT (`orchestrator/static/codemirror.bundle.js`, MIT; reproducible build in `scripts/vendor/codemirror/` — ADR 025 amended: no build step in repo/CI, the artifact checks in), served by the server's first static route (`safe_child`, 404 on missing; `create_server` verifies it ships). Domain: identity hashes stay NORMALIZED (ADR 010) but every text index went RAW-as-fetched — `new_blocks` stores raw text, tokens/mark-ranges/authorship/locked-runs index it, `missing_locked` folds whitespace on both sides instead of normalizing, and `MIN_BLAME_CHARS` died for the `has_words` rule (word-free separators stay unmarkable; short dialogue and fences are first-class). `next_record(known_texts=)` re-emits any hash whose stored text drifted — the same mechanism auto-migrates pre-054 normalized-text sidecars on the first `rebuild()` (no wipe; old RANGED marks may sit a token off on heading blocks, accepted). The wire is document-level: `GET /api/prose/doc` (raw body + `base` hash-sequence digest as the concurrency token + `block_offsets`-derived segments + absolute-offset merged spans; offsets are code points, the page converts to UTF-16 at the edge), `POST /api/prose/save` (whole-document under the route lock; base mismatch 409 → conflict banner, keep-mine/take-theirs; autosave ~2.5s rides WP44 roll-up; still bypasses the locked guard — human authority), `POST /api/prose/marks` (BATCH: one selection gesture = one lock hold = one sidecar rewrite via `NodeHistorian.record_marks`, all-or-nothing validation, change-only requests drop out; `char_range_to_tokens` is the only place char offsets become tokens — nothing offset-shaped stored), and `GET /api/prose/events?space` (SSE version bumps: the historian's `on_record` hook → the bridge's thread-safe counter, polled like `/events`; an open clean page reconciles bot edits in place by minimal-diff transaction, scroll/selection preserved). Decorations live in a CM `StateField` and MAP through local edits, so highlights ride the words while typing; nothing ever blanks (POST responses patch in place; home/diff views render detached and swap). Retired: `/api/prose/node|mark|edit`, the bridge's `node_view`/`set_mark`/`edit_block`, `glue`/`token_lens`; gate order unchanged and re-pinned on the new POSTs.
- **Turn activity streams into the chat (ADR 029, WP19).** `Orchestrator.handle_message` takes an optional per-call `observer: TurnObserver | None` (async `turn_started`/`decision`/`tool_result`, fired beside the `turn_log` taps; observers must not raise; `/mode`//`/clear` turns never stream). The Anytype bot's sink (`orchestrator/turn_activity.py`) claims the "Processing…" placeholder as a live activity message edited in place (edits reach clients instantly over their SSE subscription; coalesced ≥2s apart for the ~1 req/s API budget), the reply posts fresh, and `close` DELETES the trace message once the reply is delivered (the turn log keeps the record; a failed delete degrades to a `✓ n tool calls · m decisions` summary edit so "working…" never strands). Detail is a MODE property — `ModeSpec.activity_detail` (`off | minimal | tools | full`, default `minimal`), set on the Activity Mode object's `gc_mode_activity_detail` field (seed TOMLs can pre-fill it, ADR 035) — so switching modes switches verbosity; `off` = the pre-WP19 placeholder-becomes-reply lifecycle. The renderer (`ActivityLog`) alone interprets levels; scheduled turns and Discord don't stream.
- **Web search is a mode property, server-side only (ADR 030, WP20).** `ModeSpec.web_search` (default off; the Activity Mode object's `gc_mode_web_search` checkbox — seed TOMLs can pre-fill it, ADR 035) admits Anthropic's server-side search tool for that mode's decisions — the pipeline forwards the flag on every `decide()`, the subscription driver re-admits exactly the `WebSearch` built-in (ADR 007's `tools=[]` boundary otherwise intact), the API driver appends the `web_search_*` tool block and resumes `pause_turn` in-decide. Searches never execute on the harness (the egress firewall never sees them); they surface as `LLMTurn.server_tool_calls` in the turn log and activity stream — never as pipeline work. A searching decision's raw result payloads ride the decision event (WP22: `server_tool_results`, opaque JSON, turn-local like thinking), so the next decide replays what the search returned — verbatim blocks with `encrypted_content` intact on the API driver, a `search_digest` call/result pair in the text transcript on the subscription driver; the diary logs digests, never raw payloads. On the API driver a cited reply's text blocks (the API splits one block per cited span) fold their citations in as inline `[domain](url)` markdown links and ADJACENT text blocks concatenate verbatim (`turn_from_response`, ADR 036 amendment) — the marks conversion renders them clickable in chat; the subscription driver's SDK exposes no citations, so there this stays prompt-driven.
- **Thinking, output cap, and search limits are mode properties (ADR 037, WP29).** Five Activity Mode fields — `gc_mode_thinking` select (a level = adaptive thinking at that `output_config.effort`; Off = disabled, rejected loudly for Fable/Mythos which cannot turn thinking off; EMPTY select = deployment default), `gc_mode_max_tokens`, `gc_mode_search_max_uses`, `gc_mode_search_allowed_domains`/`_blocked_domains` (at most one list; inert without `web_search`) — flow as ONE frozen `DecideOptions` value (`modes.decide_options(spec)`) into every `decide()`; vocabulary in `domain/thinking_choice.py`. Precedence: mode level > `GC_DRIVER_EFFORT` > model default. The API driver always requests adaptive thinking EXPLICITLY with `display: "summarized"` (omitted = empty thinking text); the subscription driver maps a level onto SDK `effort` and skips the rest with one warning. `build_driver` also wires `on_result` → `TurnLog.usage`, so per-decide tokens/cost land in the diary instead of being discarded.
- **The model is a mode property too (ADR 033, WP24).** `ModeSpec.model` pins which Claude model runs a mode's decisions — canonical choices `sonnet 5` | `opus 4.8` | `fable 5` (`domain/model_choice.py` maps them to full provider ids); empty = the deployment default (`GC_DRIVER_MODEL` or the driver's own). Set on the Activity Mode object's `gc_mode_model` select (options pre-seeded by bootstrap; seed TOMLs can pre-fill it, ADR 035). The pipeline resolves the choice and passes `model=` on every `decide()` as a per-decision override on both driver paths; intent nodes stamp the resolved id, and `/mode` reports `model: <choice|default>`.
- **Files flow both ways through the chat (ADR 032, WP23).** Quirk C10 (spike S13): `POST /files` uploads (multipart, MIME-sniffed, flat response), `GET /files/:id` serves raw bytes, and inbound chat messages expose their attachment envelopes. Inbound: the bot classifies from facts before downloading (`classify_attachment`; 5MB image / 200KB text caps) — text files fold into the user message as fenced blocks, images ride `TranscriptEvent.images` (turn-local, like thinking) into native image blocks on both drivers (the SDK driver switches `query()` to the message-dict form), everything else degrades to a name+size note. Outbound: the `send_file` tool (bound in every mode) queues into the turn-scoped `Services.outbox`; the pipeline drains it into `file` reply events; the Anytype transport uploads and attaches a file card, other surfaces render the content fenced.
- **Working turns card their process trace on the reply (ADR 038, WP30).** A turn that ran tools, searched, or produced thinking mints an intent node even WITHOUT mutations (deliberately supersedes WP7's read-only-writes-nothing; plain answers still write nothing) whose body carries the full background process — `orchestrator/process_trace.py`'s `ProcessTrace` folds thinking/interim text/calls/search digests/results beside the observer and turn-log taps, rendered ONCE at creation into `### gc:process` (write-once body policy intact; the trace string crosses into `IntentRecorder.record_turn(process_trace=...)` as plain data, so application never imports orchestrator). `_finish_turn` returns the node and the pipeline stamps `ReplyEvent.attach`; the Anytype transport merges those ids ahead of text-scraped refs into the reply's first-chunk object cards (dedupe, cap 8). WP19's live activity message still deletes on close — it is scaffolding; the card is the durable record. Card visibility is mode config (ADR 046, WP38): the `gc_mode_hide_intent_card` checkbox keeps the trace card off replies (the node is still recorded), and `gc_mode_hide_node_cards` keeps the turn's created/edited nodes from carding — the pipeline stamps the drained mutation ids on `ReplyEvent.suppress` and the transport filters its text-scrape (explicit `attach` never filtered; read-only mentions still card); both default to showing.
- **Outbound chat text converts markdown to marks (ADR 036, WP28).** The chat UI renders message text as plain text (quirk C7), so `AnytypeChatClient._message_body` runs every outbound message (replies, activity edits, file captions) through `infrastructure/anytype/marks.py`: markdown links and bare URLs become clickable `link` marks, bold/italic/strikethrough/inline code map to mark types, fenced blocks pass through verbatim, underscore emphasis is never parsed (`gc_` keys). Quirk C11 (spike S14): offsets are UTF-16 code units and an invalid range 500s — which the client retries — so the converter bounds-validates every mark against the emitted text; malformed syntax degrades to literal text, never to a bad range. Inbound marks are ignored.
- **Chats title themselves (ADR 031, WP21).** After an untitled chat's first real exchange the bot makes one driver side-call and renames the chat via the generic object PATCH (quirk C9: `/chats/:cid` has no GET/PATCH; `PATCH /objects/:cid` works and shows in the re-list) — human titles are never overwritten, failures never fail the turn (`ChatTitler` policy in the transport, I/O in `anytype_chat_bot._maybe_title`).
- **Activity modes are in-space ONLY; profiles are deprecated (ADR 035, WP26).** The space's `gc_activity_mode` objects are the sole live source of mode specs — `modes.load_registry(in_space, space_context)` takes the two store payloads and nothing else. A modes TOML never merges at load anymore: `GC_MODES_FILE`/a binding's `modes_file` (else the packaged `interface/mode_seeds/<profile>.toml`) SEEDS starter objects exactly once into a space with ZERO Activity Mode objects (`infrastructure/anytype/mode_seeder.py`: mints the corpus + the Example Mode explainer, links the marked default on the Space Context when that link is empty; archived objects never block or get touched). The memory backend pre-fills its stores with the same payloads (dev/CLI ≡ a freshly seeded space) and the eval runner overlays `[[case.modes]]` on the profile's corpus. Validation lives in `interface/mode_config.py` (`spec_from_mapping`/`slugify` — layering-neutral; nothing imports the orchestrator). What remains of `DomainProfile` (tool docs, role overrides, timeline pair, ranking) is marked DEPRECATED for WP27 — do not add profile fields; new config belongs in the space or deployment config.
- **The space picks the starting mode on its Space Context object (ADR 034, WP25).** The seeded `gc_space_context` singleton (display "Space Context", infra role, read through the `SpaceContextStore` port) links the Activity Mode object NEW chats start in via `gc_default_mode` — an `objects` relation on `SYSTEM_RELATION_DENYLIST`, so it never reflects as a graph edge or edge vocabulary. The loader resolves the link by object id at every registry (re)load: an empty link (or no object) falls back to the alphabetically first mode (ADR 035 amendment; the starter-mode seeder links the corpus's marked default automatically); two settings objects, a multi-target link, or a dangling link fail loudly naming the object (startup) or degrade (the `/mode` refresh), and relinking applies within one change tick (ADR 044) — or on the next `/mode` — without a restart. This supersedes WP21's `spaces.toml` `default_mode` key (now a loud migration error); persisted per-chat modes always win.

## Conventions

Follow **CLEAN** principles in all code: **C**ohesive (one reason to change per module), **L**oosely coupled (depend on ports/abstractions, not concretions), **E**ncapsulated (no reaching into internals — tests included), **A**ssertive (objects act on their own state rather than interrogating others'), **N**on-redundant (a rule or fact lives in exactly one place). The repo-specific rules below are applications of these:

1. **Business rules live in exactly one place** — edge legality in `GraphIndex.add_edge`, creation invariants in `schema.validate_new_node`, summary staleness in `NodeWriter`. Re-checking a rule in a second layer means it's in the wrong place.
2. **Domain stays pure**: no I/O, no `httpx`, no MCP types, no clocks — this keeps `tests/unit` in milliseconds.
3. Services take dependencies via constructor, typed against ports; a new tool ≈ a new application service shaped like `Explorer`.
4. Parameter objects mirror the tool surface (`ExploreQuery` ↔ the `explore` tool schema); keep them in lockstep.
5. Test names state behavior (`test_failed_link_rolls_back_the_created_node`), grouped in classes per scenario; fixtures build worlds through public APIs, never by poking internals.
